# 记忆潮汐 · Memory Tide

> **记忆不死于过期，死于没人再想起。**

所有笔记工具都在帮你记得更多。这一个帮你退潮。

它扫你的 markdown 笔记库，找出**很久没被打开、也没被别的笔记链接过**的那些，写成一封信问你还留不留：

```
**#1**
关于：轮滑鞋尺码
最后动过：136 天前 · 被其它笔记引用 0 次
水位：0.255（潮线 0.35）

> 我想把它沉到底层。还想留着的话，告诉我。

回复：
```

**沉默 = 保留。删除要两次点头。脚本永远不删你的文件。**

## 30 秒试一下

```bash
git clone https://github.com/Mr-Jino/memory-tide.git
cd memory-tide
node scripts/tide.mjs scan examples/demo-vault
```

零依赖，Node 20+ 就能跑。示例库里有一篇被别的笔记链接过（`咖啡与睡眠`），它的水位在潮线以上——**不被需要的沉下去，被引用过的不沉**，就这一条判据。

拿到自己的库上跑：

```bash
node scripts/tide.mjs scan "你的笔记目录"          # 默认观察窗 90 天，一封最多 5 条
node scripts/tide.mjs scan "你的笔记目录" --dry     # 只打印，不落盘
node scripts/tide.mjs reply "你的笔记目录/潮汐日记/2026-10-29.md"   # 收答复
```

## 回执怎么读

| 你写的 | 发生什么 |
|---|---|
| `同意` | 下沉一层，文件一个字不动，还搜得到；第二次同意才提示可以物理删除 |
| `拒绝` | 新鲜度回满、触动 +0.3，捞回水面；拒绝 3 次以后不再问 |
| 留空 | **保留**，只是下次隔更久再问 |
| 写了别的字 | 记下来按未回复处理，**永远不猜** |

## 装成 Skill

这个仓库本身就是一个 skill（`SKILL.md`），放进你的 agent 技能目录即可：

```bash
# Codex / Claude Code 等
cp -r memory-tide ~/.codex/skills/memory-tide
```

之后你可以直接说「帮我看看笔记库里哪些东西很久没碰了」，它会跑退潮、读信、帮你答复。

## 三个可以抄走的零件

即使你不用这个脚本，这三块也可以独立搬进你自己的记忆系统。完整推导和踩坑记录见 [`references/article.md`](references/article.md) 与 [`references/design.md`](references/design.md)。

### 1. 写入的四道闸门

```
只抽第一人称自述；第三方不抽，除非它影响本人生活节奏
抽取结果必须以「用户名」开头 —— 格式判据，误伤率近零
按时间尺度分衰减：关系/事实 0.004、偏好 0.01、临时状态 0.15（每天）
置信度 < 0.7 不入库，进待确认队列，下次写信问一句「记得对不对」
附则：相对时间必须落地成绝对日期，落地失败就丢弃
```

### 2. 计价协议：看过 ≠ 想起

```
候选池被捞出来   +0.02，不回满新鲜度   ← 只是被看过
真在回答里被引用 +0.1，  回满新鲜度   ← 这才算想起
引用判定跑在回答之后；判定失败退回字面重叠（保守，宁可少算）
```

如果"被检索到"就给权重，冷层永远形同虚设——每次检索都会把一大片东西捞回热层。

### 3. 删除的同意协议

```
沉默 = 保留；删除 = 两次点头；拒绝 3 次 = 永久免疫
真实的记忆难删（两次），可能是假的记忆好删（一次）
提案只放摘要、不放原文；候选由脚本按分数挑，模型只负责写得好听
```

## 它不是什么

- **不是通用记忆框架。** mem0、Letta、Zep 都比它工程化。它只解决一件事：一个人的东西太多以后，怎么**退潮**。
- **不自动删除。** 这是它存在的理由，也是它最不方便的地方——它需要你真的看一眼那封信。
- **不省空间。** 十年约 180MB。真正的瓶颈不是磁盘，是"每轮能带进上下文的记忆预算"。
- **不联网、不上云、不调模型。** 纯本地，只看文件的修改时间和链接关系。

## 一个小坦白

示例实现里新鲜度用的是**半衰期指数衰减**（半衰期 69 天）。原始设计稿用的是线性的「每天减 0.01」——那个版本有个已知缺陷：所有超过 100 天的笔记会一起归零，被引用过的和没被引用的再也分不开。文章第六节把这个漏洞写出来了，示例实现顺手改了。
